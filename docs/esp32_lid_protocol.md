## 1. Pi → ESP32

| 줄 | 동작 |
|---|---|
| `LID_OPEN` | 열림 위치로: 열림 스위치가 있으면 눌릴 때까지, 없으면 센 위치가 열림이 될 때까지 |
| `LID_CLOSE` | 닫힘 위치로, 같은 방식 |
| `LID_STOP` | 즉시 정지 (센 위치는 유지 → 다음 명령이 그 자리에서 이어감) |
| `LID_STATUS` | 지금 상태를 `LID_STATE:...` 로 한 번 보냄 |

위치는 스텝 수로 센다: 0 = 닫힘, `LID_OPEN_STEPS` = 열림. ESP32 가 켜질 때 열림 스위치만 눌려 있으면 열림,
그 밖에는 **닫혀 있다고 본다** → ESP32 를 켜거나 USB 를 다시 꽂기 전에 뚜껑을 손으로 닫아 둔다.
이미 그 위치면 움직이지 않고 바로 응답한다(스위치 없이 닫힌 뚜껑을 또 닫으며 끝에 부딪히지 않게).

## 2. ESP32 → Pi

| 줄 | 뜻 |
|---|---|
| `LID_OPENED` | **열림 리미트 스위치로 확인됨** (이것만 Pi 가 "열림 성공"으로 본다) |
| `LID_OPEN_STEPS_DONE` | 스텝 수만큼 돌았지만 센서 확인 없음 → Pi 는 `OPEN_UNCONFIRMED` 로 보고 |
| `LID_CLOSED` / `LID_CLOSE_STEPS_DONE` | 닫힘, 위와 같은 구분 |
| `LID_STOPPED` | `LID_STOP` 으로 멈춤 |
| `BUSY:LID_OPEN` | 움직이는 중에 또 명령이 옴(무시함). 값은 지금 하고 있는 동작 |
| `LID_ERROR:<이유>` | `TIMEOUT`(끝 위치를 지나 30 % 더 가도 스위치가 안 눌림), `DRIVER_FAULT`(DRV8825 FAULT), `BOTH_LIMITS`(스위치 이상) |
| `LID_STATE:<OPEN\|CLOSED\|MOVING\|UNKNOWN>` | 스위치가 하나라도 있으면 2 Hz 로 계속. 스위치로 확인한 값만 OPEN/CLOSED, 나머지는 UNKNOWN. 스위치가 없으면 계속 보내지 않고 `LID_STATUS` 에만 답한다(늘 `UNKNOWN`) |

Pi 는 뚜껑이 닫혀 있지 않으면(`OPEN`, `MOVING`, `UNKNOWN`) 출발하지 않는다. `LID_STATE` 가 안 오면
시작할 때 닫혀 있다고 가정한다(`assume_closed_at_start: true`, 운영자가 눈으로 확인).

## 3. 배선·설정 확인 목록 (펌웨어에 넣기 전)

* **DRV8825 전류 제한**: 모터 정격 전류에 맞춰 Vref 를 조정 (Pololu 형 보드: 전류 = Vref × 2). 정격 확인 전에는 낮게.
* VMOT 8.2~45 V, VMOT–GND 사이 **100 µF 이상 전해 커패시터**. 전원이 켜진 채로 모터 선을 뽑거나 꽂지 않는다.
* RST·SLP 는 HIGH 로 (보드에 따라 두 핀을 서로 연결). EN 은 LOW = 켜짐 (GND 에 묶었으면 `LID_PIN_EN = -1`).
* ESP32 GND 와 드라이버 GND 를 공통으로. DRV8825 입력은 3.3 V 로직으로 구동 가능.
* **ESP32-S3-N16R8 에서 피할 GPIO**: 26~32 (플래시), 33~37 (옥탈 PSRAM, R8 모델), 0·3·45·46 (부팅 스트래핑),
  19·20 (USB). 실제 핀은 배선 후 정한다.
* 마이크로스텝(M0~M2)과 **열림까지 스텝 수**, **열림 방향(DIR 레벨)**, 속도·가속은 실물에서 정한다.
  처음에는 `LID_OPEN_STEPS` 를 작게 두고 손으로 막을 수 있는 상태에서 방향부터 확인한다.
* 리미트 스위치가 있으면 끝 위치에서 확실히 눌리는지, 둘 다 눌리는 경우가 없는지 확인한다.
* Pi 에서 포트 이름은 `ls -l /dev/serial/by-id/` 로 확인한다(재부팅하면 ttyACM0/ttyUSB0 순서가 바뀔 수 있음).
  ESP32-S3 보드의 "USB"(내장 USB)와 "COM/UART"(변환 칩) 중 어느 쪽 포트에 `Serial` 이 나오는지는
  Arduino 설정 "USB CDC On Boot" 에 따라 다르다.

### 스위치 없이 쓸 때 (지금 구성)

* ESP32 는 **켜질 때 뚜껑이 닫혀 있다고 보고** 거기서부터 스텝을 센다. 전원을 넣거나 USB 를 다시 꽂거나
  펌웨어를 올리기 전에 뚜껑을 손으로 닫는다. 열린 채로 리셋되면 다음 `LID_CLOSE` 는 "이미 닫힘"으로 보고
  움직이지 않는다(그때는 손으로 닫고 리셋).
* 스텝모터가 막혀서(손·짐·전류 부족) 스텝을 잃으면 센 위치와 실제가 어긋난다. 전류(Vref)와 속도는
  여유 있게, 뚜껑 경로에 걸릴 것이 없게 한다. 닫힐 때 끝(기구 멈춤턱)에 세게 부딪히면
  `LID_OPEN_STEPS` 를 조금 줄인다.
* Pi 화면/로그에는 `OPEN_UNCONFIRMED`(열림 확인 안 됨), `CLOSED_UNCONFIRMED` 로 나온다 → 운영자가 눈으로 확인.

## 4. 안전

* 주행 중에는 Pi 가 뚜껑 명령을 보내지 않는다(도착 + 정지 확인 후에만, 복구용 `CLOSE` 는 IDLE 에서도).
  펌웨어도 스텝 수 상한으로 끝나므로 스위치가 고장 나도 모터가 계속 돌지는 않는다(`LID_ERROR:TIMEOUT`).
* 뚜껑이 열리면 LiDAR 뒤쪽 약 157° 가 가려진다 → 열린 채로 주행 금지.
  지금은 `delivery_demo` 가 닫힘 전에는 출발시키지 않는다(수동 조종은 막지 않으니 주의).

## 5. 시험한 것 / 안 한 것

* 한 것(클라우드 PC): 참고 펌웨어를 가짜 Arduino 함수(시간·핀·모터·스위치 흉내)로 컴파일해 스위치 없음 /
  둘 다 있음 / 닫힘 스위치만 있음 세 경우의 응답(위 표), 위치 추적(중간 정지 후 정확히 0 으로 복귀),
  최고 속도·감속, BUSY, FAULT, TIMEOUT, BOTH_LIMITS 를 확인했다. Pi 쪽은 `mock_lid_esp32` 로 전체 흐름 시험.
* 안 한 것: ESP32 툴체인 컴파일, 실제 보드·드라이버·모터·스위치. 실물에서는 시리얼 터미널(115200)로
  `LID_STATUS` → `LID_OPEN` → `LID_STOP` → `LID_CLOSE` 순서로 먼저 확인한다.
