# STM32 주행 프로토콜 (Pi ↔ STM32) — 펌웨어 담당용

작성 2026-11-02. Pi 쪽 구현: `src/robot_base` (`base_bridge_node`, 줄 형식 `robot_base/protocol.py`).
펌웨어 없이 Pi 쪽을 시험하는 가짜 STM32: `ros2 launch robot_base base.launch.py mock:=true`.

## 1. 부호·단위·순서

* 바퀴 순서: **FL, FR, RL, RR** (앞왼, 앞오, 뒤왼, 뒤오)
* 조향각 `a`: **0.1° 단위 정수**, 0 = 정면, **+ = 왼쪽**(위에서 볼 때 반시계)
* 바퀴 속도 `r`: **0.1 rpm 단위 정수**, + = 바퀴가 향한 방향으로 전진
* 숫자는 모두 정수(`sscanf("%d")` / `atoi` 로 읽으면 된다)

## 2. Pi → STM32

### DRV (주행) — 20 Hz 로 계속 옴 (정지 중에도 0 으로 옴)
```
DRV,<seq>,<a_fl>,<a_fr>,<a_rl>,<a_rr>,<r_fl>,<r_fr>,<r_rl>,<r_rr>
```
* `seq`: 0~65535 순번(넘치면 0). 빠진 줄 확인용, 처리는 선택.
* 앞바퀴 각은 왼쪽·오른쪽이 **다를 수 있다**(애커먼: 안쪽 바퀴가 더 꺾임). 각자 그대로 서보에 준다.
* `a_rl`, `a_rr` 는 항상 0 (뒷바퀴 서보 없음, 무시해도 됨).
* 바퀴 속도도 4개가 다르다(곡선에서 바깥 바퀴가 빠름). 각자 그대로 모터에 준다.
* Pi 가 이미 조향 범위·최고 속도 안의 값만 보내고, 조향이 덜 돌았으면 바퀴 속도를 0 으로 보낸다.
  그래도 펌웨어는 **기계 한계로 다시 제한**(clamp)한다.

예 (0.3 m/s 이하 실제 계산값):

| 상황 | 줄 |
|---|---|
| 정지 | `DRV,17,0,0,0,0,0,0,0,0` |
| 직진 0.2 m/s | `DRV,17,0,0,0,0,223,223,223,223` |
| 좌회전 v=0.2 m/s, w=0.15 rad/s | `DRV,17,234,160,0,0,194,279,178,268` |
| 우회전 v=0.2 m/s, w=−0.15 rad/s | `DRV,17,-160,-234,0,0,279,194,268,178` |

### 기존 명령 (팀원 상태기계가 보냄, Pi 가 그대로 전달)
| 줄 | 동작 | 응답 |
|---|---|---|
| `STOP` | 바퀴 즉시 0 (다음 DRV 의 0 아닌 속도부터 다시 움직임) | `ACK,STOP` |
| `ESTOP` | 바퀴 즉시 0, **래치**: RESET 전까지 DRV 무시 | `STATE,EMERGENCY_STOP` |
| `RESET` | ESTOP 래치 해제 | `ACK,RESET` |

## 3. STM32 → Pi

### FB (피드백) — 50 Hz 권장 (최소 20 Hz)
```
FB,<t_ms>,<a_fl>,<a_fr>,<a_rl>,<a_rr>,<r_fl>,<r_fr>,<r_rl>,<r_rr>
```
* `t_ms`: STM32 밀리초 카운터(HAL_GetTick, 넘쳐도 됨). Pi 가 적분 간격 계산에 쓴다.
* `r_*`: **측정한** 바퀴 속도(엔코더/홀 센서). Pi 의 `/wheel/odom` 은 이 값으로 계산된다 → 정확해야 함.
* `a_*`: 측정한 조향각. 서보에 위치 측정이 없으면 **마지막 명령값**을 보내고 Pi 설정
  `steer_feedback: false` 로 바꾼다(그때 Pi 는 서보 속도 모델로 기다린다).
* FB 가 0.3 s 끊기면 Pi 는 링크 끊김으로 보고 정지 + `/estop_state=true`.

### EST (E-stop 상태) — 10 Hz 이상 계속
```
EST,0     (정상)
EST,1     (E-stop 눌림)
```
하드웨어 E-stop 버튼 입력을 그대로 보낸다. 0.5 s 끊기면 Pi 는 E-stop 으로 본다.
**버튼은 소프트웨어와 별개로 모터 전원을 직접 끊어야 한다.**

### 상태 문자열 (선택, 팀원 상태기계가 씀)
`DRIVE_MOVING` (서 있다가 움직이기 시작할 때 한 번), `DRIVE_STOPPED` (멈췄을 때 한 번).
그 밖의 줄은 Pi 의 `/stm32_status` 로 그대로 넘어간다.

### IMU (선택, 지금은 없음)
`IMU,<t_ms>,<gx>,<gy>,<gz>,<ax>,<ay>,<az>` — mrad/s, mm/s². 보내면 `/imu/data` 가 된다.

## 4. 펌웨어가 꼭 지켜야 할 것

1. **워치독**: 유효한 DRV 가 **300 ms** 동안 없으면 바퀴 속도 0 (조향은 그대로). Pi·USB 가 죽어도 멈춰야 한다.
2. **한계**: 조향각은 기계 한계로, 바퀴 속도는 모터 정격으로 다시 제한.
3. **ESTOP 래치**: `ESTOP` 또는 버튼 → RESET/버튼 해제 전까지 움직이지 않음.
4. **명령과 실제 불일치 감시**(권장): 명령 0 인데 바퀴가 돈다, 측정 속도가 명령보다 훨씬 크다 → 정지 + 래치
   (`docs/vision_hazard_design.md` 5절 "모터 급발진").
5. 줄 길이 200자 이하, 모르는 줄은 무시(또는 `ERROR,INVALID_COMMAND`).

## 5. 선택: 체크섬

줄 끝에 `*HH` (`*` 앞 모든 문자의 XOR, 16진 대문자 2자리, NMEA 와 같음)를 붙일 수 있다.
Pi 는 받은 줄에 체크섬이 있으면 검사하고, 보낼 때는 설정 `use_checksum` 을 따른다.

## 6. 펌웨어 쪽 단독 시험 (시리얼 터미널)

```
DRV,1,0,0,0,0,100,100,100,100      ← 네 바퀴 10 rpm 전진, 300 ms 안에 다시 안 보내면 멈춰야 함
DRV,2,300,300,0,0,0,0,0,0          ← 앞바퀴 왼쪽 30°
ESTOP / RESET / STOP               ← 응답 확인
```
FB 가 50 Hz 로, EST 가 10 Hz 로 계속 나오는지 확인한다.
